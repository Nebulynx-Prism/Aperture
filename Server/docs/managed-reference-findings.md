# Managed Virtual Desktop reference findings

This is **reflection-only metadata and bounded IL inspection**, deeper than the earlier file inventory but not complete decompilation or runtime observation. The collector uses Windows PowerShell/.NET Framework `Assembly.ReflectionOnlyLoadFrom` and `ReflectionOnlyLoad`, `GetMethodBody`, framework opcode descriptors and `Module.ResolveMember`/`ResolveString` where possible. It never invokes target methods, evaluates target fields, instantiates target objects/custom attributes, or loads target assemblies into the execution context. Constructors and static constructors appear only as metadata/IL; they were not run.

Artifacts: [collector](../tools/inspect_managed_reference.ps1), [bounded machine evidence](managed-reference.json), [prior inventory identities](reference-artifacts.json). Run `& ./tools/inspect_managed_reference.ps1` in Windows PowerShell, with optional `-Paths` and `-OutputPath`. No SDK, engine, REA, package download or installation is needed.

## Specific IL observations

Tokens below are scoped to the assembly/MVID in JSON; offsets are byte offsets within a method. Obfuscated names are preserved literally in machine evidence and represented by tokens here for readability.

- **Service hosting boundary:** Service assembly, `VirtualDesktop.Service.Service`, method **0x06000042** (341 IL bytes). IL_004E constructs `System.ServiceModel.ServiceHost(Object, Uri[])`; IL_0059 constructs `System.ServiceModel.NetNamedPipeBinding(NetNamedPipeSecurityMode)` after `ldc.i4.0` at IL_0058; IL_005F loads `TimeSpan.MaxValue`, followed by `Binding.set_ReceiveTimeout` at IL_0064. These are direct instruction/token observations. **Inference:** this method contains WCF named-pipe hosting setup, unlike Prism's custom newline-JSON pipe. The endpoint address, registration, caller authorization and actual live transport behavior were not established. The captured timeout setter does not establish a timeout policy for every operation.
- **Service contract and handlers:** `VirtualDesktop.Interfaces.IServiceManager` metadata names Connect, Disconnect, UseRealtimePriority, DisableProcessThrottling, RestartOVRService, SetOpenXRRuntime and others. Interface methods have no IL bodies. Actual `ServiceManager` implementations were captured, including **0x06000060** `Void DisableProcessThrottling(Int32, Boolean)` (120 bytes), **0x0600005F** UseRealtimePriority (98), **0x0600005D** Connect (188), **0x06000063** RestartOVRService (142), and **0x06000066** SetOpenXRRuntime (845). The throttling body contains branch-heavy IL and a call at IL_0053 to an obfuscated member with signature `Boolean [obfuscated](IntPtr, [obfuscated type])`. This is not enough to identify its underlying Win32 API, flags or semantics. No equivalence to Prism's implementation is claimed.
- **Connection setup:** Streamer assembly, `VirtualDesktop.Streamer.ConnectionManager`, method **0x06000181** (795 bytes) includes `newobj VirtualDesktop.Net.NetMessagingClient(IPEndPoint)` at IL_00A9, construction of `EventHandler<NetMessage>` at IL_00D5, and a call taking that handler at IL_00DA. **Inference:** there is an endpoint-oriented client and message callback relationship. No port, handshake, framing, encryption or compatibility has been recovered.
- **Message representation:** Streamer `VirtualDesktop.Net.NetMessage`, constructor **0x0602149C** (145 bytes) stores byte-array, integer and boolean fields, constructs an obfuscated stream-like type from `(Byte[], Int32, Int32)` at IL_002B, and constructs a wrapper taking `System.IO.Stream` at IL_003C. Selected method **0x060214AF** (115 bytes) stores an async task builder, Stream and CancellationToken into a nested state-machine type. Captured nested method **0x060214B3** (851 bytes) accesses message buffers and state. These support a buffer/stream/async implementation boundary; they do not establish message layout, field meanings, byte order, or a wire ABI.
- **Desktop graphics:** Streamer `VirtualDesktop.Streamer.DesktopStreamer` constructor **0x060004AD** (487 bytes) references `SharpDX.Toolkit.GameServiceRegistry` and `SharpDX.Toolkit.Content.ContentManager`. Method **0x060004B1** (960 bytes) references `IMonitorDuplication` and `MonitorInfo[]`; **0x060004BF** (552 bytes) includes `SharpDX.DXGI.Output.WaitForVerticalBlank()` at IL_0094. These are graphics/monitor-related code references, not proof of a particular active capture pipeline or compositor texture protocol. The largest selected body, **0x060004BB** (2,671 bytes), has a deliberately truncated 2,048-byte raw prefix.
- **Older Server executable:** selected `VirtualDesktop.Server.DesktopManager` bodies reference `IntPtr` and `ThreadLocal<IntPtr>` fields; nested method **0x06000100** references an obfuscated `VirtualDesktop.Win32.User32` method taking Int32 and returning IntPtr. `VirtualDesktop.Server.Program` method **0x06000098** has 1,102 bytes of IL, with only the first bounded instruction sample decoded. No window-station, desktop-switching, or request-dispatch behavior is asserted from these type/signature references.

## Resolution and interpretation limits

Dependency loading was restricted to reflection-only GAC/name resolution, then sibling DLLs in the supplied installation directories; nothing was downloaded or executed. The dependency-attempt cap of **128** was reached. Two preload failures were recorded: `System.Net.Http, Version=4.2.0.0` and `System.IO.Compression, Version=4.2.0.0`. Streamer GetTypes returned a partial result with one loader error for System.Net.Http; Service and Server had no GetTypes loader errors. Missing dependencies were left unresolved rather than substituted or installed.

Decoded samples resolved **201 / 104 / 348** member references for Service / Server / Streamer. They retained **3 / 0 / 8** token-resolution/formatting errors, including `Cannot convert value to type System.String`; raw token and operand bytes remain available. Generic context is not supplied to ResolveMember, so some generic tokens may fail independently of missing dependencies.

Several identifiers and call paths are obfuscated, including control-character names, delegate wrappers and indirect string providers. The collector does not execute decoders, static initializers or delegates to reveal values. A decoded `call` is a static reference; it does not prove reachability or successful execution. No control-flow graph, exception-region reconstruction, symbolic execution or high-level source recovery was attempted. Branch/switch operands are captured as bytes, not interpreted into inferred business logic. String literals, where resolved, are data and are not treated as behavioral proof.

Bounds: at most 8 selected types and 25 selected method bodies per assembly, 5 per type, 2,048 raw IL bytes and 64 decoded instructions per method. Type method inventories are capped at 80 entries, matching-type name samples at 100. Top-level types precede nested types; selection favors named service implementations/constructors, then larger non-special bodies rather than event accessors. Truncation flags distinguish partial capture from complete bodies. JSON output is refused above 3 million characters.

## Validation and relevance to Prism

PowerShell parser and machine-evidence validation checked reflection-only status, three matching file hashes, base64 IL lengths, bounded instruction offsets and the expected WCF constructor references. No installed executable, service, headset runtime or APK was launched or modified. No current parent tests or live headless run was interrupted.

This evidence establishes actual managed method/type/IL boundaries that the earlier inventory could not show. It does **not** provide Virtual Desktop protocol compatibility, a usable driver ABI, a shared-memory offset contract, or full PCVR. Current Prism service throttling was separately implemented by the parent using SetProcessInformation(ProcessPowerThrottling); that implementation was not inferred from Virtual Desktop's obfuscated method and was not modified here. Parent will re-run the updated service tests.
